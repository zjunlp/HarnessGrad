## What it measures

TextWorld household tasks: the agent is told "put a clean mug in the cabinet" and has to act through a text interface — `go to`, `take`, `heat`, `put` — until the game says the goal is reached. Solved means the goal was reached within **50 actions**; there is no partial credit per task.


Study on **100** ids from the official `train` split; each pool below is scored once per checkpoint. `valid_unseen` is ALFWorld's own out-of-distribution evaluation split; `valid_seen` and `valid_train` are its two other evaluation splits.

## Run it

- study: 100 ids from `train` (`train100.csv`), 10 rounds, whole set per round
- measure: every saved round on each split. The budget is **48 machine-wide slots**; `--jobs` is how many of them one invocation may use. The checkpoint sweeps ran **two shards at `--jobs 24`**, which is what keeps the two cards balanced: one call-level balancer in front of both servers, so every model call goes to whichever card is free.
- score: the environment's own verifier; per-task verdicts are kept, so a score recomputes from `per_task`

```bash
# study
HG_ALFWORLD_STUDY_IDS=train100.csv HG_ALFWORLD_POOL=valid_unseen \
  python3 driver.py --harness loop --dataset alfworld --split declared --side train \
  --rounds 10 --trials 1 --jobs 24 --improver dsh \
  --method-entrypoint 'python3 methods/<method>/run.py' --run-id <id> --runs-root runs

# one saved checkpoint on one split
HG_ALFWORLD_STUDY_IDS=train100.csv HG_ALFWORLD_POOL=valid_unseen \
  python3 driver.py --harness loop --dataset alfworld --split declared --side eval \
  --from-run <id> --from-round <N> --trials 1 --jobs 24 --improver none \
  --run-id <id>-ckpt-r<N>-valid_unseen --runs-root runs
```
