Each page here is one benchmark. A benchmark with published measurements carries the same five things: what it measures and how its tasks are split, the scores this platform measured, the exact configuration those runs used, where the full trajectories live, and how to submit a result of your own. A benchmark whose adapter is merged but which has not produced a valid point yet says so on its own page, and publishes **no number**.

A score is published only when it can be traced to per-task verdicts: a point that measured 139 of a pool's 140 tasks is excluded and named, never averaged in. The frozen reference (H0, the base harness on the same tasks) is printed with every table, because a raw number without it does not say whether a method helped.

| --- | --- | --- | ---: | --- |
| [ALFWorld](alfworld/) | 100 study / 134 eval | study `train`, eval `valid_unseen`, plus `valid_seen` and `valid_train` | 43 on `valid_unseen`, 41 on `valid_seen`, 41 on `valid_train` | measured |
| [AppWorld](appworld/) | 732 released | study `train`, dev `dev`, test `test_normal` + `test_challenge` | — | in progress |
| [LoCoMo](locomo/) | 10 conversations / 1,986 questions | none — the benchmark declares no study/eval split | — | in progress |

An *in progress* page is not a result and is not counted anywhere: it exists so that the question "does this platform cover AppWorld?" has an answer that distinguishes "the adapter is merged" from "we measured it". Integration status is tracked in the repository's [`registry/dataset-blockers.json`](https://github.com/zjunlp/HarnessGrad/blob/main/registry/dataset-blockers.json).
