# Public legacy launch review

The legacy server accepted unauthenticated, side-effecting GET requests to launch a driver without shared budget arguments; overwrite could delete run evidence and the stop endpoint used fuzzy process matching. Adding budget arguments alone would retain those unsafe behaviors. Both GET and POST `/api/run` and `/api/stop/<id>` now explicitly return 410; direct `start_job` and `stop_job` also reject without spawning, deleting, or signaling. This is a deliberate compatibility break; use the Console with its explicitly configured deployment-owned shared budget. Direct CLI optional budget semantics are unchanged. No machine-specific capacity or endpoint was introduced.

The existing slot stamp initialization can observe an empty stamp created by another process and accept it; consequently this change does not claim to resolve concurrent capacity initialization or secure a mutable budget directory. Operators must protect and consistently provision shared directories and capacities. Other legacy endpoints still have side effects, including prepare, settings, promotion, and model connection; the legacy server is not safe to expose to untrusted clients. Their redesign is outside this change. The legacy options response no longer exposes the configured agent API key.

Addendum: legacy settings and options blank malformed or credential-bearing endpoint URLs for display, report configured/redacted status, and retain the existing blank-means-unchanged write behavior. Explicit replacement still works. Clean HTTP(S) URLs remain visible. This does not make the other legacy mutating routes safe.
