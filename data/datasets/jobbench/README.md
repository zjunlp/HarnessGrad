# jobbench: native source and execution contract

This port inventories the original task tree pinned in `SOURCE.json`, without
importing upstream or Harbor into the measurement runtime. It does not pretend
that terminal snapshot verification is the native separate/replay protocol.

```sh
python3 data/datasets/jobbench/prepare.py --root /path/to/jobbench
HG_DATA_JOBBENCH=/path/to/jobbench python3 -c \
  'from data.datasets import jobbench as d; print(d.provision_status())'
```

Preparation is explicit; importing/loading never downloads or installs anything.
The manifest records the source revision and each downloaded file SHA-256.
Preparation refuses links and pre-existing conflicting files. Native task content,
including `task.toml`, original instructions, images, private tests, collect hooks,
resource/network policies and separate environment declarations remains intact.
`inventory()` returns all selected source tasks and their declarations/digests;
public actor tasks only contain the native instruction and a namespaced ID.

`load()` inventories public tasks without requiring unselected runtimes. Selected `SETUP` / `VERIFY` access validates the task/source-bound native runtime manifest before actor/model work. It uses a private native-world relay and fresh Harbor verifier replay, with missing dependencies/images reported as ConfigMissing rather than scored zero. See [shared runtime preparation](../../scaffolds/native_harbor_runtime/README.md).

Native execution requirements preserved by the route:
- `--render` explicitly runs the author's pinned renderer; it requires the
  author's Python dependencies and pinned HF raw data. `HG_JOBBENCH_COLLECTION`
  chooses `main` (default), `easy` or `all` once tasks are generated;
- a fresh separate rubric-verifier image, artifact-only deliverable export and
  independent judge credentials through the verifier-only broker;
- official weighted rubric blocks and mean of per-task rewards. Do not report
  an unweighted pass-rate or cross-task weight sum as the headline score.

## Renderer preparation runtime

`--render` runs the original pinned author's `fetch_snapshot` and `generate` in
an explicitly selected `jobbench_renderer` preparation artifact. The platform
interpreter remains stdlib-only. This profile is separate from Harbor execution
and judge runtimes; rendering does not establish execution admission or a score.

```sh
python3 data/datasets/jobbench/prepare.py --prepare-runtime \
  --runtime-root /outside/platform/renderer-runtimes
python3 data/datasets/jobbench/prepare.py --check-runtime \
  --runtime-root /outside/platform/renderer-runtimes
python3 data/datasets/jobbench/prepare.py --root /outside/platform/jobbench \
  --render --runtime-root /outside/platform/renderer-runtimes
```

Only `--prepare-runtime` installs packages into its external managed artifact.
`--check-runtime` is read-only and never fetches source or installs packages.
Missing renderer configuration fails before source download/extraction when
`--render` is selected. Existing UV cache/offline settings apply to explicit
runtime preparation. Rendering still explicitly fetches the raw HF source pinned
in `SOURCE.json`; `HF_ENDPOINT` and HF token variables apply only to that trusted
preparation worker, never the actor.

The fixed `660b33a86ed032559df0b2fdc1ad38cf7ceb83f3` renderer's actual dependency
boundary is narrow: `generate`/`render` use stdlib, and `hf_source.fetch_snapshot`
imports Hugging Face Hub lazily. The lock therefore contains Hub and its complete
15-package closure, including its PyYaml dependency. Harbor is not imported by
this path; the author's generated verifier/environment requirements are copied
unchanged and are not installed into this renderer or the platform.

`RENDERER_SOURCE.json` pins the actual imported renderer source, templates,
original judge/helpers and license. Before import and after generation, both
parent and worker re-admit those bytes and the exact managed artifact. Unlisted
renderer/template/helper files (including old generated bytecode), links, source drift and a resolved HF revision differing
from the data pin are rejected. Worker/controller/source-pin bytes are recorded
separately. Successful receipts live at `renderer-attempt-*/receipt.json`; failed
attempts retain only private worker diagnostics and never publish a success
receipt. Original generated manifests, data pins, scorer files and license bytes
remain unchanged. Use a fresh source root when older manual imports left
unlisted files; never repair or erase prior prepared evidence automatically.
The source and dependency receipts are not an OS/container
isolation claim or benchmark execution evidence.

Offline authored controls use actual pinned source files, the real Hub library
and a loopback synthetic HF HTTP API. They render one invented task and exercise
metadata/blob selection, errors, revision mismatch and source-content drift:

```sh
HG_JOBBENCH_RENDERER_TEST_SOURCE=/outside/pinned-source-only-files \
HG_JOBBENCH_RENDERER_TEST_STORE=/outside/managed-renderer-store \
pytest -q tests/quality/test_jobbench_renderer_runtime.py --basetemp=/tmp/jobbench-renderer-controls
```

These controls do not fetch released tasks, call models, build containers or
establish full-dataset generation parity. Source-only fixture files must match
the recorded renderer hashes; the test never replaces upstream functions.
