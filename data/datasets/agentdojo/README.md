# AgentDojo managed execution

The relay and verifier use one explicitly prepared Python 3.12 execution artifact.
Both declarations carry role bindings; launch admission verifies the exact selected
artifact, including its venv inventory and base executable. The verifier starts
with `-I -B` and calls the existing `bridge.evaluate` API under that interpreter.
It no longer starts platform `python3` or projects/copies a historical venv.
Official utility, attacker-success predicates, suite v1.2.2 and the registered
`ignore_previous` attack are unchanged.

`execution-requirements.lock` preserves every dependency pin in the historical
`_src/runtime-requirements.lock`. Its local AgentDojo source reference is represented
separately: commit `089ed468cf3ed0322acc66b0211f26d9d90dbf60`, package version
0.1.35, archive SHA-256 `d7e0ee021be27a69e7e66647979b5a5e0dd10030d38d04ce4102e18a76a228d8`.
`source-manifest.json` records all 112 package file digests from that archive.
Bootstrap checks its own manifest pin and every source file before importing the
package. Missing, changed, extra files, links and stale bytecode are refused.
No model/provider health is established by preparation.

## Explicit preparation

Keep the artifact store and clean source outside the checkout. For example:

```bash
export HG_DATASET_RUNTIME_ROOT=/absolute/cache/agentdojo-runtimes
export HG_AGENTDOJO_SOURCE_ROOT=/absolute/cache/agentdojo-source/src
export HG_DATA_AGENTDOJO=/absolute/datasets/agentdojo
python tools/prepare_dataset.py --dataset agentdojo --runtime execution
python -B data/datasets/agentdojo/prepare.py \
  --archive "$HG_DATA_AGENTDOJO/_src/agentdojo.tar.gz" \
  --source-target "$HG_AGENTDOJO_SOURCE_ROOT"
python -B data/datasets/agentdojo/prepare.py --check-only
```

Source preparation requires a fresh physical directory, checks the archive digest,
and extracts only the exact expected regular files. It never copies an installed
venv. Legacy runtimes and published artifacts remain untouched. Existing source
trees containing bytecode must be replaced by a fresh extraction at a new location.
Without `HG_AGENTDOJO_SOURCE_ROOT`, the source path defaults to the historical
`_src/agentdojo-<commit>/src`; the same strict inventory checks still apply.

`--check-only` installs nothing and starts no task, scorer or service. It freshly
checks the managed runtime, clean source and prepared catalog/case/oracle digests.
`prepared-manifest.json` pins the historical 949 pairs for the fixed attack using
catalog and aggregate case/oracle SHA-256 values, without containing private text.
A changed preparation is not silently reused. Initial snapshots are not execution
inputs and are not included in this gate.

For fresh case generation, use the selected artifact's `bin/python -I -B` with
`prepare.py --prepare-cases`; this deliberately runs upstream snapshot/oracle APIs
and refuses an existing prepared directory. It is separate from the read-only gate.
The obsolete tool-only venv is no longer generated by the CLI or projected to actors.

## Scope and controls

The service mounts only declared code, pinned source and the selected private case
read-only. The actor gets the standard-library CLI and socket, never source, task
predicates, oracle files or environment snapshots. Source identity is separate from
the dependency artifact identity. Host system libraries and the base standard
library remain compatibility inputs; this is not an immutable OS image.

Offline declaration/privacy tests require no prepared runtime. To opt in to native
synthetic controls after explicit preparation:

```bash
HG_AGENTDOJO_EXECUTION_TEST_STORE="$HG_DATASET_RUNTIME_ROOT" \
HG_AGENTDOJO_EXECUTION_TEST_SOURCE="$HG_AGENTDOJO_SOURCE_ROOT" \
python -m pytest -q tests/quality/test_agentdojo_execution_runtime.py \
  --basetemp=/tmp/hg-agentdojo-controls
```

Those controls use a fake evaluate API and synthetic relay handler. They verify
score sensitivity, selected interpreter, source admission and read-only prefixes;
they do not execute official tasks, model calls or benchmark episodes.
