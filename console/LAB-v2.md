## 4. 实验室（重做，只保留"造"）

两个 tab，各自是一条**流水线**，每一步都要能看懂"我在哪一步、下一步是什么"。
右侧固定一块「送到实验」，两个流程共用（起点 / 题集 / 轮数 / 阻塞项 / 等效命令 / 复制 / 启动按钮禁用并写明 M4）。

### A. 产出 Harness

| 步 | 内容 |
| --- | --- |
| 1 起点 | 选 `Base_Harness/loop` 或某个 run 的某一轮；显示 sha、文件数、该轮已有的改动摘要（**链接到版本**，不在这里展开 diff） |
| 2 想改什么 | 一句话说明 + 期望影响哪类失败（这是给人看的声明，**不是**平台记录，界面要标注） |
| 3 送到实验 | 用这个起点去测：题集、轮数、并发、阻塞项、等效命令 |

M4 之前第 2 步只读（不做编辑器），按钮写明"编辑要等 M4"，第 3 步的"启动"禁用。

### B. 产出 RSI 方法

| 步 | 内容 |
| --- | --- |
| 1 语料 | 方法列表，**分组**：`方法` / `对照组`（a、b、echo_base、noop、raise_step_cap）/ `脚手架`（lim_improver 等）；每行显示 title、kind、deviations 条数、能否作为起点 |
| 2 借什么 | 选中一个方法 → 只显示它的 **deviations 列表**（"与上游的差异"就是可借鉴的正文）+ `run.py` 的文档字符串摘要（不显示全文，全文在版本无关的只读弹层里可选） |
| 3 协议 | `methods/protocol.py` 的原文 docstring（服务端读）+ 必须实现的三件事 + 需要的规则测试文件路径 |
| 4 骨架与送到实验 | 生成的 `run.py` 骨架 + `method.json` 模板（只读、可复制）+ 校验状态（有 run.py / 有规则测试 / 字段齐全）+ 等效命令 |
