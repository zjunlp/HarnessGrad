## 2. 对话里的技能（本版做“可信的卡片”，不做不可信的模型调用）

一个技能 = 一张**结构化卡片**，不是一句提示词。它们全部是只读 + 预览：
`GET` 读数据、生成命令、给出阻塞项。**真正的编辑与起跑是 M4**，卡片上写明。

### 技能 A：`/harness` —— 为一个场景造/改 harness

| 步 | 内容 |
| --- | --- |
| 1 场景 | 选场景（具身 / 科学 / 其他）+ 数据集适配器 + 题池 + **基线 harness**（现有 7 个：`loop`、`loop_plain`、`dsh_agent`、`cli_agent`、`codex_agent`、`loop_rrsi_parse`、`oracle`） |
| 2 看现状 | **文件系统面板**：目录树 + 带行号的代码视图；点行/拖选 → 底部 chip 显示 `agent.py:120-133 · 14 行`，可复制为锚点 |
| 3 声明改动 | 一句话说明（标注：人的声明，不是平台记录）+ 引用第 2 步的锚点；生成 **patch 请求预览**（M4 才执行） |
| 4 送到实验 | 题集/轮数/并发/阻塞项/等效命令/复制/启动（禁用） |

**这一条就是"给定场景造专用 harness"的入口**：第 1 步选场景与数据集，第 4 步发一次多轮改进 run，
产物是**第 N 轮的那个 harness**（带曲线、每轮 sha、逐题轨迹）。前置条件在卡片里明说：
该场景必须已有数据集适配器；没有的（如 OceanGym）先要适配器，那是代码活，技能只能生成骨架。

### 技能 B：`/method` —— 提出一个 RSI 方法

| 步 | 内容 |
| --- | --- |
| 1 语料 | 分组：**方法** / **对照组**（`a`、`b`、`echo_base`、`noop`、`raise_step_cap`）/ **脚手架**（`lim_improver`）；每行 title、kind、deviations 条数、能否作为起点 |
| 2 借什么 | 选中方法的 deviations 列表 + 一句摘要（不塞全文） |
| 3 协议 | `methods/protocol.py` 原文（服务端读）+ 三个必须实现的东西 + 规则测试路径 |
| 4 骨架 | 生成的 `run.py` 骨架 + `method.json` 模板（只读、可复制） |
| 5 送到实验 | 校验状态（有 run.py / 规则测试 / 字段齐全）+ 等效命令 + 阻塞项 |

## 3. 文件系统面板（本版唯一的“新”部件）

- 左：目录树（只读）；中：带行号代码（只读，长文件截断并标注）；
- **行选择**：单击选中一行、Shift 点击选一段；选中的行高亮，底部出现 `path:start-end · N 行` 与「复制锚点」「在版本里打开」；
- 选择只存在浏览器里，不写任何文件；它唯一的去向是第 3 步的 patch 请求预览。

## 4. 不做

- 不做编辑器、不做真起跑、不做工具调用（M4）；卡片上必须写明当前只能预览。
- 对话在本版**不需要模型端点**：技能卡是确定性的界面，配了端点也只是 M4 之后的事。
- 不新增非 GET 请求（验收会数）。
