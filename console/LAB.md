# 实验室（Lab）· 目标形态与重构规格

> **已过时 —— 历史记录，不是现状。** 这份笔记描述的「实验室 / 对话 / 技能卡 / 方法页」
> 已经从 console 里整块删除（屏、路由、按钮、徽章都删了）。现在的三屏是 实验 / 轨迹 /
> 版本，见 `README.md` 的「删掉了什么（以及为什么）」。文件留着只作决策记录。

> 取代原先的「版本」和「方法」两个屏，并删掉「对比」屏。
> 依据：2026-10-19 的讨论 —— 方法是"做出来"的，不是列出来看的；harness 也是。
> 两者共用一条流水线：**选起点 → 在文件系统里改 → 送到实验去验**。

## 1. 导航

```
对话
实验        （跑过的、正在跑的）
实验室      （本轮新增：两个 tab）
```

- 「版本」并入实验室的 **Harness** tab（保留它现在的三栏：文件树 / diff / 事实卡）；
- 「方法」并入实验室的 **方法** tab（重做，见 §4）；
- 「对比」**删除**：它唯一独有的是"同一方法 train 与三个 eval 池并排"，收进实验详情的一小块（§5）。
- **兼容**：`#/harness…` 与 `#/methods` 必须继续可用（重定向到 `#/lab?tab=…`），验收套件按这些 hash 写的。

## 2. 实验室的骨架

```
┌ tab：Harness | 方法 ───────────────────────────────┐
│ 左：起点 / 语料        中：文件与改动        右：送到实验 │
└──────────────────────────────────────────────────┘
```

右侧「送到实验」在两个 tab 里是**同一个面板**，这是整个重构的重点：实验室不自己产出结论，
它只产出一次**可被实验检验的请求**。

## 3. Harness tab（由现在的「版本」演进）

- 左：选择起点
  - 已有 run 的某一轮（现在的行为）；
  - `Base_Harness/loop`（基线）；
  - 提示：选中的状态就是"从这里出发"的起点。
- 中：文件树 + 逐轮 diff（保持现状：两组分层、按文件分组、新旧双行号）。
- 右（新）：**送到实验**
  - 显示这次要验的东西：起点、harness sha、题集（100 题 / 三个池）、并发与轮数；
  - 显示**阻塞项**（有 driver 在跑 → 拒绝；验真请求要 GPU 窗口）；
  - 显示等效命令，可复制；
  - 「启动」按钮在 M4 之前一直**禁用**，并写明原因（不是灰色假装）。

## 4. 方法 tab（重做）

左：**语料**（这是你要的"文件系统里有其他 RSI 方法可以借鉴"）

- 9 个方法，每个一行：`title` · `kind` · 与上游差异条数 · 能否作为起点（有 `run.py`、有规则测试）；
- 点开进入方法目录的文件系统：`run.py`、`method.json`、以及该方法自己的额外文件（如 `dgm/archive.py`、`dgm/staged_eval.py`）；
- 顶部固定一块**协议说明**（读 `methods/protocol.py` 的文档字符串）：方法从 stdin 读一个 JSON、往 `trajectory_out` 写一份候选、**不自己打分**。

中：文件内容（只读展示，带行号）。这一版**不做编辑器** —— 编辑在 M4 之后，理由写在面板里。

右：**送到实验** + 校验状态

- 校验：规则测试是否存在并通过、协议字段是否齐全（`method.json` 的 kind/title/note）；
- 借鉴提示：列出该方法与上游的差异条目（来自 `method.json.deviations`），这是"可以借什么"的正文；
- 送到实验：`--method <name>` 的等效命令 + 阻塞项。

## 5. 实验侧的联动

2. 若该 run 的方法在语料里存在，详情里给一个回链「在实验室看这个方法」。
